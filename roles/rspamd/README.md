# Ansible Role: rspamd

An Ansible Role that installs [Rspamd](https://rspamd.com/) spam filtering with DKIM signing on Debian and Ubuntu servers.

## Role Variables

Available variables can be found in [defaults/main.yml](defaults/main.yml)

## Example Playbook

```yaml
    - hosts: all

      vars:
        rspamd_worker_controller_password: '$2$...'
        dkim_domains:
          example.com:
            selector: mail
            key_size: 2048

      roles:
        - alphanodes.setup.rspamd
```

## Controller Password

`rspamd_worker_controller_password` expects a hash, not the plain password. Generate it on the target server with `rspamadm pw` and use the same plain password to log in to the web UI.

## DKIM and DNS

Keys for all domains in `dkim_domains` are generated by the dkim role. Publish the TXT record from `/var/lib/dkim/<domain>/<selector>.txt`, see the [dkim role](../dkim/README.md).

## Postfix Integration

Postfix talks to rspamd via milter on `localhost:11332`. The postfix role configures this with `postfix_with_rspamd: true`, set `postfix_smtpd_proxy_filter_smtp` and `postfix_smtpd_proxy_filter_submission` to an empty string to disable the proxy filter.

## Spam Header for Filtering on the MDA Side

Rspamd emits no `X-Spam-Flag`, and its default `X-Spam-Status` header is present on every message, spam or not. A Sieve rule matching `X-Spam-Flag` therefore never fires. Enable `rspamd_with_spam_header` to mark every message that reached the `add_header` action, and keep name and value in sync with the dovecot role:

```yaml
rspamd_with_spam_header: true
rspamd_spam_header_name: X-Spam
rspamd_spam_header_value: 'Yes'

dovecot_spam_header_name: X-Spam
dovecot_spam_header_value: 'Yes'
```

This changes what users see: mail scoring at or above `rspamd_action_add_header` moves from the inbox into the Junk folder. Check `rspamc stat` for the share of affected messages before enabling it.

## Bayes Classifier

With `rspamd_bayes_autolearn: true` the classifier starts learning from rspamd's own verdict. Verify after a few days that both statfiles grow and reach `min_learns` (200 per class):

```bash
rspamc stat | grep -E "Statfile|Messages learned"
```

## Diagnosing Slow Scans

Set `rspamd_log_level: info` temporarily. Rspamd then logs one line per message with the total scan time, the DNS request count and the fired symbols:

```bash
journalctl -u rspamd --since "-24 hours" -o cat | grep -oE "time: [0-9.]+ms, dns req: [0-9]+"
```

Outgoing mail carries the `LOCAL_OUTBOUND` symbol and can be filtered out separately. Scan times clustering on an exact value (4000 ms, 8000 ms) point at a timeout rather than slow processing, and a `*_FAIL` symbol such as `RSPAMD_URIBL_FAIL` names the check that gave up. Set the level back to `warning` afterwards, `info` logs every message.
